# 승인된 비바리움 도감 작업 지침

사용자 검수·승인: 2026-11-04. 현재 대화의 최신 지시가 이 문서보다 우선한다. 이 파일이 PC·AI 공통 프롬프트의 단일 원본이다. 모델의 기억이나 이전 대화 자동 전달에 의존하지 않는다.

목표는 한국어 도감에서 생물을 찾고 정체·관리·크기·구매 정보를 구분해 판단할 수 있게 하는 것이다.

## 1. 원본과 시작

- GitHub 저장소가 최신 원본이다. 지정 브랜치·인계 커밋을 우선한다.
- 원격·브랜치·미커밋 변경·인계 커밋 포함 여부를 확인한다. README, AGENTS, HANDOFF와 연결된 계획·장부를 읽는다.
- 기존 변경을 보존하며 reset·clean·덮어쓰기·강제 푸시를 하지 않는다. 다른 PC의 경로·도구·인증·브라우저 상태를 가정하지 않는다.

## 2. 목표와 우선순위

- 특정 수량을 완료 기준으로 삼지 않고 실제 취미 분류와 확인된 누락 후보로 확장한다. 신규 추가와 기존 정보 심화를 함께 진행한다.
- 정글플랜트·지피·덩굴·브로멜리아, 게코·개구리를 우선한다. 달팽이·육지소라게 추가 심화는 후순위다.

## 3. 분류와 이름

- 기존 ID 유지. 상품·규격·모프를 별도 종으로 중복 등록하지 않는다.
- 종·속 수준·품종/교잡종·미확정 유통명을 구별한다. 식물은 속→종/유통항목→품종, 동물 모프·패턴·지역형은 부모 아래에 둔다.
- 한국 통용명을 대표로 쓰고 학명·별칭을 보존한다. 탐색 분류와 공식 분류를 구별하며 판매명으로 종·아종·유전 모프를 확정하지 않는다.

## 4. 조사

- 기존 자료·장부를 재사용하고 부족한 필드·충돌 해결에 필요한 검색만 한다. 한 업체를 전체 시장/인기로 일반화하지 않는다.
- 학명은 공식 분류 자료, 관리는 종별 생태·전문 사육/재배 자료, 국내 취급·가격은 실제 국내 상품으로 각각 확인한다.
- 해당 종·날짜·측정 기준·한계를 확인한다. 접근 실패·충돌은 기록하고 독립 작업을 계속한다. 실패 반복·검색 노출 수로 사실을 추정하지 않는다.

## 5. 장부와 완료

- 업체×카테고리×확인일 단위로 표시 총수·방문 페이지·중복 제거 수를 대조한다.
- 상품별 기존 연결 후보·신규 후보·품종/모프·보류·제외를 기록한다. 이름 대조를 실물 동정 완료로 세지 않는다.
- 목록 열람·후보 처리·정보 입력·검증 완료를 구별한다. 항목 수/입력률을 생물학적 완성도로 쓰지 않는다.
- 최소 URL·확인일·보류 사유를 남긴다.

## 6. 관리와 크기

- 분류군 설명을 모든 종에 복사하지 않는다. 습도·환기·분무 후 마름·수역·배수·계절성·공간을 구분한다.
- 환경 태그는 합사 보증이 아니다. 온습도·급이·보충제 수치를 만들거나 서로 평균내지 않는다.
- 성체/성숙과 측정부위를 명시한다. 전체길이·몸길이·갑장·잎 길이·높이·군락 폭을 섞지 않는다.
- 판매 당시 크기·화분·성숙 개시 크기를 성체 최대값으로 쓰지 않는다. 잎 크기만 있는 식물의 전체 크기 필터는 미확인이다. 하한/최대값 추정 금지.

## 7. 가격과 링크

- 국내 공개 표시가와 시장 평균·실거래가·적정가를 구별한다. 모프·성별·연령·품종·규격 혼합 범위를 명시한다.
- 개체·쌍·묶음·촉·컵·포트·판 단위별로 나눈다. 주문수량1개를 생물1마리/식물1촉으로 해석하지 않는다. 단위 미확인 신규 가격은 보류한다.
- 상품·카테고리·모바일 중복을 제거하며 도서·장난감·용품·키트·동명 다른 종을 제외한다.
- 확인일·직접 상품 링크를 연결한다. 상품·홈페이지·SNS·문의 링크를 구별하고 품절을 유지한다. 목록 존재는 현재 재고 보장이 아니다.
- 제공 가격표는 게시일·출처 유형을 구분한다.
- 추가 승인: 기본 화면에 상품·문의 링크와 구매처 탭을 노출하지 않는다. 입력칸 밖에서 숫자5를 독립적으로 연속5회 눌러 현재 페이지에서만 해제한다. 다른 키/입력은 연속 횟수를 초기화하며 길게 누르기·조합키는 해제에 사용하지 않는다. 새로고침/새 방문은 잠금으로 시작한다. 화면에 해제 안내를 상시 표시하지 않는다. 가격은 유지한다.
- 이 방식은 UI 숨김이다. 공개 저장소·JSON의 URL을 보호하는 인증/접근 통제가 아니며 다른 사람이 절대 열람할 수 없다고 주장하지 않는다.

## 8. 인기와 사진

- 가격·신규 발견·노출·모프 수로 인기 순위를 만들지 않는다. 여러 독립 판매처의 비교 가능한 자료와 명시한 기준을 사용한다. 지점·규격·모프 중복 제거, 미확인은 미집계 유지.
- 사진은 분류군 일치·이용허락·저작자·원본을 확인한다. 판매 사진 무단 복사 금지. 특정 모프·품종에 일반 사진을 대표처럼 붙이지 않고 미확보는 준비 중으로 둔다.

## 9. 화면

- 동물은 더보기 없이 전체 나열. 사진 원본 비율 유지, 상세/모프 펼침으로 사진이 커지지 않게 한다.
- 목차·검색·필터·상세·URL·뒤로가기·구매처를 연결하고 이전 검색·조건·목록 위치를 복원한다.
- 구매 링크는 위 해제 조건을 따르며 사진 권리 표기는 유지한다. 조사 원문·긴 근거 표·불필요한 구현 설명을 제품에 노출하지 않는다.

## 10. 비용과 검증

### 토큰 절약 규칙

- 같은 세션에서 이미 읽은 지침·계획·자료는 바뀐 부분만 읽는다. 새 세션에서는 공통 지침과 최신 인계를 먼저 확인한다. 과거 대화 전체·인계 기록 전체를 매번 다시 읽지 않는다.
- 파일 검색은 rg로 대상 경로·파일 유형·키워드를 좁힌 뒤 필요한 줄만 읽는다. 대형 JSON·HTML·로그·diff 전문을 출력하지 말고 개수·ID·변경 필드·관련 문장으로 요약한다.
- 이미 확보한 후보 목록·최소 근거·확인일·보류 사유를 먼저 재사용한다. 조사 원문이 새 PC에 없으면 장부에 있는 관련 URL만 다시 확인한다. 기존 카테고리 전체를 이유 없이 재수집하지 않는다.
- 새 검색 전에 해결할 필드나 질문을 정한다. 같은 질문을 표현만 바꿔 반복 검색하지 않는다. 충분한 근거가 확보되면 검색을 끝낸다. 재고·가격처럼 변할 수 있는 값과 상충 자료는 절약을 이유로 검증을 생략하지 않는다.
- 독립적인 파일 읽기·검색은 묶어서 실행한다. 서로 의존하는 수정·검사·승인 절차는 순서를 지킨다. 같은 결과를 여러 도구로 중복 확인하지 않는다.
- 하위 에이전트는 기본 사용하지 않는다. 사용자 요청이나 적용 지침이 명시적으로 요구하는 경우만 사용하며, 범위를 작게 나누고 같은 조사를 중복 배정하지 않는다.
- 항목마다 전체 검사를 반복하지 않는다. 데이터 배치는 변경 항목·중복·기존 필드 보존을 국소 검사하고, 주요 묶음 끝에 전체 check와 git diff --check를 한 번 실행한다. 통과 후 새 변경·실패·미해결 문제가 있을 때만 필요한 검사를 다시 실행한다. 문서만 수정한 작업에는 도감 전체 검사를 돌리지 않고 링크·내용·diff를 확인한다.
- 브라우저는 필요한 상태·요소만 확인한다. 짧은 화면 질문에 전체 DOM을 반복 출력하거나 같은 화면을 이유 없이 반복 캡처하지 않는다. UI 변경은 대표 데스크톱/390px 흐름을 검수하며, 국소 실패가 없다면 모든 항목을 같은 방식으로 반복 클릭하지 않는다.
- 중간 보고는 의미 있는 완료·발견·방향 변경 때 짧게 전달한다. 이미 보고한 계획·수치·설명을 반복하지 않고 최종 답변도 핵심 변경·검증·남은 문제 중심으로 쓴다.
- 작은 작업마다 계속할지 질문하지 않는다. 불확실성이 실제 결과를 좌우하거나 필요한 승인인 경우만 질문하고, 답변과 독립적인 작업은 계속한다.
- 인계에는 현재 브랜치·커밋·완료 범위·변경 파일·재현 가능한 검사·미완료·다음 우선 작업만 남긴다. 오래된 스냅샷을 최신 상태와 혼동하지 않게 구별한다. 긴 대화나 원문을 복제해 여러 최신본을 만들지 않는다.
- 토큰 사용량이나 잔여량을 도구 없이 추정해 보고하지 않는다. 확인 가능한 사용 한도가 있으면 사용자 요청에 따라 확인하고 10%를 남긴다.
- 토큰 절약은 정확성·사용자 승인·사진 권리·데이터 보존·필수 검사를 생략할 이유가 아니다. 모르는 값을 추정해서 채우지 않는다.

결함은 재현·회귀검사 후 수정한다. 자동 검사·실제 화면 확인·사람 평가를 구별하고 도구 불가 상태를 완료로 주장하지 않는다.

## 11. 실행과 보고

- 승인 계획은 작은 단계마다 계속할지 묻지 않고 실행한다. 짧은 중간 보고는 발견·완료 묶음·다음 해결 대상 중심이다.
- 검토 가능한 묶음과 인계 기록, 해당 명시 파일만 로컬 커밋한다. 원문 HTML·캐시·인증·개인정보는 공개 저장소에서 제외한다.
- 추가 업로드·main 반영·공개 배포는 최종 보고 후 사용자 지시를 따른다.
- 변경·검증·남은 문제·로컬/원격 반영을 구별한다. 일부 묶음 완료를 전체 도감 완료로 표현하지 않는다.
